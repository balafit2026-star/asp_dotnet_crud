# Create the JobApi project from scratch

This guide records how to scaffold and configure the ASP.NET Core backend in this repository.

## Requirements

- Windows PowerShell (commands below use PowerShell syntax)
- .NET 10 SDK
- SQL Server, such as SQL Server Express or LocalDB
- Internet access to restore NuGet packages
- Optional: Visual Studio or VS Code

Confirm that the .NET SDK is installed:

```powershell
dotnet --version
```

The project targets `net10.0`; install the .NET 10 SDK if this prints a different major version or the `dotnet new` command cannot find `net10.0`.

## 1. Create the Web API project

Choose a parent folder where you want the source directory created, then run:

```powershell
cd D:\path\to\your\projects
dotnet new webapi --name JobApi --framework net10.0 --use-controllers
cd .\JobApi
```

This creates `JobApi.csproj` and the ASP.NET Core Web API starter files.

## 2. Install project packages

Install the SQL Server Entity Framework Core provider, EF Core tooling package, and Swagger UI package. These versions match this repository's `.csproj`:

```powershell
dotnet add .\JobApi.csproj package Microsoft.EntityFrameworkCore.SqlServer --version 10.0.12
dotnet add .\JobApi.csproj package Microsoft.EntityFrameworkCore.Tools --version 10.0.12
dotnet add .\JobApi.csproj package Swashbuckle.AspNetCore --version 10.2.3
```

The project also references `Microsoft.AspNetCore.OpenApi` version `10.0.12`, which is included by the .NET 10 Web API template. If it is not in the generated `.csproj`, add it explicitly:

```powershell
dotnet add .\JobApi.csproj package Microsoft.AspNetCore.OpenApi --version 10.0.12
```

Install the EF command-line tool globally to create and apply migrations:

```powershell
dotnet tool install --global dotnet-ef
```

If it is already installed, update it instead:

```powershell
dotnet tool update --global dotnet-ef
```

Check installation:

```powershell
dotnet ef --version
```

## 3. Add the job model and database context

Create these folders if they do not already exist:

```powershell
New-Item -ItemType Directory -Force -Path .\Models, .\Data, .\Controllers
```

Create `Models/Job.cs`:

```csharp
namespace JobApi.Models;

public class Job
{
    public int Id { get; set; }
    public string Title { get; set; } = string.Empty;
}
```

Create `Data/AppDbContext.cs`:

```csharp
using JobApi.Models;
using Microsoft.EntityFrameworkCore;

namespace JobApi.Data;

public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options)
    {
    }

    public DbSet<Job> Jobs => Set<Job>();
}
```

## 4. Configure the SQL Server connection

Add a `ConnectionStrings` section to `appsettings.json` (or edit the existing one):

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost\\SQLEXPRESS01;Database=JobPortalDb;Trusted_Connection=True;TrustServerCertificate=True"
  }
}
```

The server name must match the SQL Server instance installed on your machine. Common alternatives:

```text
Server=localhost;Database=JobPortalDb;Trusted_Connection=True;TrustServerCertificate=True
Server=(localdb)\MSSQLLocalDB;Database=JobPortalDb;Trusted_Connection=True;TrustServerCertificate=True
```

Keep the JSON backslash escaped as `\\`. For SQL authentication, configure a connection string using `User Id` and `Password`; do not commit real credentials. The SQL Server service must be running, and the configured account must have permission to create the database and tables.

## 5. Register Entity Framework and controllers

In `Program.cs`, register controllers and the SQL Server database context using the configured connection string. Ensure the Swagger services and middleware are enabled for Development. The relevant registration is:

```csharp
using JobApi.Data;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();
builder.Services.AddOpenApi();

var app = builder.Build();

if (app.Environment.IsDevelopment())
{
    app.MapOpenApi();
    app.UseSwagger();
    app.MapSwaggerUI();
}

app.UseHttpsRedirection();
app.MapControllers();
app.Run();
```

Keep any additional endpoints generated by the template if you want them. `app.MapControllers()` is required for attribute-routed API controllers.

## 6. Create the jobs controller

Create `Controllers/JobDto.cs`:

```csharp
namespace JobApi.JobDto;

public class CreateJobRequest
{
    public string Title { get; set; } = string.Empty;
}

public class UpdateJobRequest
{
    public int Id { get; set; }
    public string Title { get; set; } = string.Empty;
}
```

Create `Controllers/JobsController.cs` with routes for listing, retrieving, creating, updating, checking, counting, and deleting jobs. For this repository's complete controller implementation, see `Controllers/JobsController.cs`.

## 7. Restore packages and build

From the directory containing `JobApi.csproj`:

```powershell
dotnet restore .\JobApi.csproj
dotnet build .\JobApi.csproj
```

## 8. Create and apply the database migration

Generate the initial migration from the model and context:

```powershell
dotnet ef migrations add InitialCreate --project .\JobApi.csproj
```

Apply migrations to SQL Server and create/update `JobPortalDb`:

```powershell
dotnet ef database update --project .\JobApi.csproj
```

The `Migrations` directory in this repository already contains `InitialCreate`; when recreating the project, generate it once. To apply an existing migration, run only `dotnet ef database update`.

## 9. Configure launch URLs and run

For the same development ports used by this repository, configure `Properties/launchSettings.json` with these profiles:

```json
{
  "$schema": "https://json.schemastore.org/launchsettings.json",
  "profiles": {
    "http": {
      "commandName": "Project",
      "dotnetRunMessages": true,
      "launchBrowser": false,
      "applicationUrl": "http://localhost:5246",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    },
    "https": {
      "commandName": "Project",
      "dotnetRunMessages": true,
      "launchBrowser": false,
      "applicationUrl": "https://localhost:7249;http://localhost:5246",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    }
  }
}
```

Run the HTTP profile:

```powershell
dotnet run --project .\JobApi.csproj --launch-profile http
```

Or run the HTTPS profile:

```powershell
dotnet run --project .\JobApi.csproj --launch-profile https
```

Swagger UI is available at `http://localhost:5246/swagger` or `https://localhost:7249/swagger` while running in Development. The OpenAPI JSON is at `/openapi/v1.json`.

## Rebuild and run later

After the project has been created, the typical commands from its directory are:

```powershell
dotnet restore .\JobApi.csproj
dotnet ef database update --project .\JobApi.csproj
dotnet run --project .\JobApi.csproj --launch-profile http
```
